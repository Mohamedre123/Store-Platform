# زاوية — منصة متاجر إلكترونية متكاملة

منصة SaaS لإنشاء وإدارة المتاجر الإلكترونية، مبنية للسوق المصري أولًا.

> **الاسم مؤقّت.** «زاوية» اسم عامل حاليًا وقابل للتغيير. لهذا السبب اسم المنصة
> ولونها وشعارها كلها في مكان واحد (`src/lib/brand.ts` + `.env`) — تغييره لاحقًا
> لا يمسّ الكود.

---

## التقنيات

| الطبقة | الاختيار | السبب |
|---|---|---|
| الإطار | Next.js 16 (App Router) | تصيير من الخادم يخدم السيو، ونشر بسيط على Vercel |
| الواجهة | React 19 + Tailwind CSS 4 | سرعة تطوير مع تحكّم كامل في التصميم |
| قاعدة البيانات | PostgreSQL على Supabase | علاقية، وموثوقة للطلبات والمخزون |
| الوصول للبيانات | Drizzle ORM | أنواع TypeScript كاملة، وهجرات SQL واضحة |
| التخزين | Supabase Storage | صور المنتجات والشعارات |
| المهام الخلفية | جدول `job_queue` + Vercel Cron | الرسائل والبكسل والشحن لا تعطّل العميل |

## البنية

ثلاث واجهات من نفس التطبيق، يفصل بينها المضيف في `src/proxy.ts`:

```
zawya.app              → الموقع التعريفي        src/app/page.tsx
dashboard.zawya.app    → لوحة التاجر            src/app/dashboard/**
<slug>.zawya.app       → متجر التاجر            src/app/s/[store]/**
نطاق-مخصص.com          → نفس المتجر بنطاقه       src/app/s/[store]/**
```

```
src/
  app/          الصفحات والمسارات
  db/schema/    مخطط قاعدة البيانات (11 ملفًا حسب المجال)
  lib/          أدوات مشتركة (العملة، الهواتف، النطاقات)
  proxy.ts      توجيه المضيف → الواجهة الصحيحة
```

## قواعد لا يُتهاون فيها

1. **`store_id` في كل جدول وكل استعلام.** العزل بين المتاجر مسؤولية طبقة الوصول،
   لا اجتهاد في كل صفحة. تسريب بيانات متجر لمتجر آخر هو أخطر عطل ممكن هنا.
2. **كل المبالغ أعداد صحيحة بالوحدة الصغرى (قرش).** الكسور العشرية في JavaScript
   غير دقيقة، والخطأ يتحوّل لفروق حقيقية في فواتير التجار. العرض عبر `formatMoney`
   فقط.
3. **الطلب سجل تاريخي.** اسم المنتج وسعره وتكلفته تُنسخ على بنود الطلب وقت الشراء،
   فلا يفسد طلب قديم لأن التاجر عدّل منتجًا اليوم.
4. **لا شيء بطيء في مسار العميل.** الرسائل وأحداث البكسل وإنشاء الشحنات تدخل
   `job_queue` ولا تؤخّر تأكيد الطلب.
5. **الأسرار مشفّرة في قاعدة البيانات** ولا تُرسل للمتصفح أبدًا.

## التوافق مع المتصفحات

مطلب أساسي في هذا المشروع، لأن جزءًا كبيرًا من عملاء التجار على أجهزة أندرويد
متوسطة وقديمة.

- ألوان الهوية بصيغة **hex** لا `oklch` — تعمل على المتصفحات الأقدم.
- احتياطي صريح لـ `dvh` عبر `@supports`، و`vh` هو الأصل.
- مساحات لمس ≥ 44px، والتكبير مسموح (لا `maximum-scale=1`).
- `overflow-x: hidden` على `body` ومحتوى عريض داخل حاويات تمرير مستقلة.
- احترام `prefers-reduced-motion` و`prefers-color-scheme`.
- الأرقام معزولة اتجاهيًا (`unicode-bidi: isolate`) حتى لا تنعكس داخل نص عربي.

الحد الأدنى المدعوم: Chrome 111+ · Safari 16.4+ · Firefox 128+ · Edge 111+
(متطلبات Tailwind 4). الأجهزة الأقدم من ذلك تعرض المحتوى كاملًا مع تدهور بصري
بسيط، ولا تفقد أي وظيفة.

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local   # واملأ القيم من Supabase
npm run db:push              # يبني الجداول
npm run dev
```

النطاقات الفرعية محليًا تعمل مباشرة على `http://<slug>.localhost:3000`.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm run build` | بناء الإنتاج |
| `npm run typecheck` | فحص الأنواع |
| `npm run db:generate` | توليد ملفات الهجرة |
| `npm run db:push` | تطبيق المخطط على قاعدة البيانات |
| `npm run db:studio` | واجهة استعراض البيانات |
